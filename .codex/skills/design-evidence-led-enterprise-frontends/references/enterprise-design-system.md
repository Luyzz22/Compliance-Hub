# Enterprise design system

## Visual character

Aim for calm authority, operational precision, and inspectability. The interface should look maintained by a serious product organization, not assembled from generic landing-page blocks.

## Color

- Use one interaction accent across links, selected states, focus, and primary actions.
- Build the page from a light canvas, white working surfaces, deep neutral ink, and quiet borders.
- Reserve semantic green, amber, and red for real states.
- A dark product preview may act as a bounded artifact, not a second page theme.
- Check all normal text and controls against WCAG AA contrast.

## Typography

- Use a system or deliberately licensed type stack with no unreviewed external dependency.
- Keep display weight near 600 and body weight near 400.
- Limit a screen to a small, coherent type hierarchy.
- Prevent single-word headline orphans when a nearby size or grid adjustment solves them.
- Use monospaced text only for technical identifiers, release states, and evidence metadata.

## Layout

- Prefer asymmetric editorial grids to centered hero stacks.
- Pair one claim with one artifact; do not create a second competing hero.
- Express systems as aligned rows, relationships, timelines, ledgers, or diagrams before using cards.
- Keep the main content width bounded and the reading order obvious at every breakpoint.
- Preserve existing routes, anchors, navigation labels, and analytics unless the user approves changes.

## Surfaces and shape

- Default controls to 8px radii and major media surfaces to 16px.
- Keep structural sections and data rows square.
- Use one radius per object and avoid concentric rounded containers.
- Use shadows only for elevated interactive or product artifacts.
- Prefer 1px borders and tonal separation for ordinary hierarchy.

## Motion

- Use motion to explain state change, focus, sequence, or causality.
- Favor opacity and small transform changes lasting roughly 160 to 500ms.
- Pause autoplay when focused, hovered, hidden, or reduced motion is requested.
- Avoid infinite decorative animation, parallax that obscures content, and layout-shifting hover effects.

## Product proof

- Prefer real product captures or truthful interactive models.
- Mark illustrative views explicitly.
- Never add fabricated precision, customer marks, testimonials, or integration logos.
- Keep evidence and limitations close to the claim they support.

## Anti-slop review

Reject or redesign:

- Generic centered headline, paragraph, two buttons, and floating dashboard composition
- Repeated equal three-card feature rows
- Decorative grid backgrounds, glowing blobs, and ambient gradient haze
- Excessive pills, badges, glass panels, and nested cards
- Uppercase micro-eyebrows and ornamental letter spacing
- Fake dashboards dominated by percentages and vanity metrics
- Copy that could belong to any SaaS product

Extract principles from admired products. Do not reproduce protected visual assets, brand marks, or distinctive trade dress.
